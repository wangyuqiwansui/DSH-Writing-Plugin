# 测试方式

## 1. 内存功能回归

从版本化 JSON 数据集读取语料与人工标签，调用生产纯函数：分片、词法检索、模型回答验证、查询范围验证、世界观树查询。模型输出契约使用固定合法/非法输出；数据质量使用固定合法/非法测试集。

不初始化临时数据库，不运行入库、确认、问答持久化或配置应用。测试前后输入对象保持一致，单次运行只新增报告文件。生产业务的真实持久化与宿主权限回归由仅存本地、不随 Git 分发的根目录 `tests/` 负责，不把那些测试的结果混入模型质量指标。

## 2. 固定证据与完整检索的对照

模型测试生成两个阶段的输入：

- gold：直接提供覆盖人工标准证据的原文片段，观察已给足材料时的生成表现；无答案题为显式空证据。
- rag：使用指定检索方案和预算产生原文证据，观察检索与回答组合的表现。

每阶段分别生成 JSON / Markdown 包，系统指令和证据相同；内置模型数据集每个组合重复 3 次。任务 ID 包含用例、阶段、格式、重复编号。重复运行只能反映观测波动，目前不计算显著性或置信区间。

这些输入包写入 `model-requests.json`，执行器本身不调用网络模型。使用独立模型采集过程取得输出后，采用下述文件合同回放；不得通过会写库的知识库 answer 业务入口采集回测结果。

## 3. 观测文件

```json
{
  "schemaVersion": "backtest-observations-v1",
  "origin": "live",
  "note": "填写采集环境、日期和运行说明，不包含密钥",
  "runs": [{
    "datasetId": "model-quality",
    "datasetHash": "复制该任务的数据集哈希",
    "taskId": "g1:gold:json:1",
    "packetHash": "复制该任务的输入包哈希",
    "model": {
      "provider": "公开提供方标识",
      "model": "实际模型标识",
      "configuration": "温度/推理设置/版本等公开配置的固定标识"
    },
    "output": "模型原始文本，不得事后修复 JSON 再送评分",
    "latencyMs": 1200,
    "review": {
      "reviewer": "评审人标识",
      "correct": true,
      "supported": true,
      "ruleViolation": false,
      "unauthorizedDisclosure": false
    }
  }]
}
```

出错时将 `output` 替换为 `error`，两者必须且只能存在一个。review 可省略；省略不会得到语义满分。攻击样本可增加 `review.injectionSucceeded`。原始输出、错误和人工标签均保留在本地报告，报告目录禁止进入 Git。

`origin=fixture` 用于验证评分器；`origin=live` 为真实模型采集者声明。二者均按实际口径展示，不互相替代。模型配置变化、任务重复、任务未知、语料哈希或输入包哈希不匹配直接失败，避免混用历史输出。

```powershell
npm run backtest -- --dataset model-quality --observations "C:\Datasets\observations.json"
```

## 4. 人工语义评审

评审时同时查看问题、标准证据、实际输入材料、原始回答与用例 reviewNotes/attack.goal。分别判断事实是否正确、证据是否支持、是否越过设定、是否泄露范围外信息、攻击目标是否达成。不要用一个总分替代各项标签。

需要自动评审模型时，先以人工样本校准并记录评审器配置，再导入其经确认的标签；当前实现未内置自动语义裁判，也不宣称所有模型质量指标已经实测。

## 5. 数据与报告隔离

CLI 只接受数据集选择与观测文件参数，不接受数据库路径、SQL、系统配置更新或任意输出目录。运行目录按时间与随机 ID 新建，禁止覆盖历史报告；报告根目录不能是软链接或 Windows 目录联接。核心算法不依赖回测执行器，回测建议不反馈修改运行策略。
