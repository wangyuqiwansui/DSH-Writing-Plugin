# 统一数据库初始化与模块清单

维护日期：2026-10-27。所有需要数据库的模块通过 `writingMiddleware` 的受限数据端口访问根工作台 `databasePath` 指向的 SQLite 文件；内部由 `writingStorage` 管理事务，模块不得直接调用。统一初始化器负责创建或升级整个共享库，当前目标为 schema v6；不按模块分别建库。请求与模块边界见[中间件说明](../../architecture/request-middleware.md)。

## 唯一推荐入口

在 `DSH-Writing-Plugin` 目录执行：

```powershell
$databaseFile = [IO.Path]::GetFullPath((Join-Path (Get-Location).Path 'data/novel.sqlite3'))
npm run db:init -- --db $databaseFile
```

部署到其他位置时替换为实际数据库的本机绝对路径。必须显式传入 `--db`，不默认选库。命令映射到现有 `scripts/local_db.py init`，一次按顺序执行 `storage/migrations` 中全部未应用迁移。

数据库配置页面会生成含安装目录的 `npm --prefix '<插件目录>' run db:init -- --db '<数据库路径>'`，可从任意目录执行，与上面使用同一个入口。旧 `npm run db -- --db '<路径>' init` 仅作为兼容调用保留。

初始化后，在 DSH 的“数据库”页面检查并保存同一路径。命令只管理指定文件，不改写 profile；首次初始化不填充业务资料。旧库升级需停止写入并显式执行，升级前保留备份，插件加载不会自动迁移。

## 执行与失败语义

1. 新文件：创建完整表、约束和实例，返回检查结果。
2. 已有旧库：验证身份、迁移历史与结构；升级前生成一致性备份，在事务内应用剩余迁移；保留原实例及全部业务内容。
3. 已是当前版本：复查并追加初始化回执；不重复迁移，不清空或重复插入业务数据。
4. 失败：未知数据库、未来版本、被修改的迁移、结构漂移或坏内容明确拒绝；迁移异常回滚，备份保留。新库失败可能留下空 SQLite 文件，不宣称初始化完成。

命令依赖 Python 3.10+ 及支持 STRICT/JSON/FTS5 的 SQLite；npm 用于统一入口。迁移前暂停使用该库的写入服务。初始化完成不表示已生成资料、规则、检索索引内容或完成模型配置。

检查、备份和恢复仍使用 [数据库管理命令](README.md)，它们不是额外的模块初始化步骤。

## 新模块接入规则

- 在本清单登记名称、共享库需求、迁移编号、持久化内容和实际实现状态。
- 新模块通过 `writingMiddleware` 接入明确的受限数据端口，内部复用 `writingStorage`；新表/约束通过新的连续编号迁移加入，不修改已发布 SQL，不创建模块私有初始化脚本。
- 运行统一命令即可覆盖新增迁移；同时验证空库、从既有版本升级、重复执行、数据保留与异常回滚。
- 模块启动、页面打开、热插拔只检查依赖与库状态，不隐式初始化、迁移或填充业务数据。
