# 知识处理核心

状态：2026-10-27，已实现文本 → LLM 整理 → SQLite 版本存储 → 人工确认 → RAG → LLM 带证据回答的闭环。入口为工作台「知识库」。本模块不负责小说正文生成，也不授予角色知情资格。

## 使用

1. 配置已初始化的共享数据库，选择工作台右上角的统一模型。
2. 打开「知识库」，选择现有项目，或显式创建知识库项目。
3. 粘贴文本或导入 UTF-8 TXT / Markdown，点击「整理并保存候选」。模型生成分片标题、摘要和检索关键词；原文按完整版本保留。
4. 对照原文审阅候选，点击确认。模型整理不会自动确认事实。确认前不进入 RAG；确认后也不代表来源已通过专业真实性审核。
5. 在「检索与问答」执行仅检索或模型回答。证据可以展开检查，响应可以导出。
6. 在「功能测试集」生成、审阅和导出文件快照。回测已抽离到根目录 `backtesting/`，通过独立命令运行，结果存入被 Git 忽略的 `backtest-reports/`。页面入口不执行回测或配置应用。

## 所有权和依赖

- `service.ts`：入库、读取和模型任务生命周期。
- `corpus.ts`：只通过 `KnowledgeDataPort` 访问完整版本、决定、head 和命令回执。
- `retrieval.ts`：纯函数分片、BM25 风格词法排序、证据打包；没有模型或数据库调用。
- `model-codecs.ts`：模型输入模板、严格模型响应验证。
- 回测不属于本核心：指标、执行器和数据集统一在根目录 `backtesting/`，本模块不导入执行器。
- `model-adapter.ts`：唯一宿主 LLM 适配器，经过 `writingModels.prepare()`，不给模型文件、网络、SQL 或写入工具。
- `host.ts`：组合根，装配核心与独立查询适配层。核心算法不导入查询协议、浏览器页面或基础设施数据库实现。
- `client/`：管理资料、问答展示，组合独立的测试集导出组件；业务消费者应使用[独立查询合同](../knowledge-query/README.md)。

## 存储

复用 schema v6 的 001/002/004，无新表、无新迁移。模块加载或打开页面不初始化库。数据端口实现位于 `src/infrastructure/storage/knowledge-data.ts`，经过 `writingMiddleware.data('knowledge')`。

| 产物 | kind / schema | 内容 |
| --- | --- | --- |
| 原始资料 | knowledge_source / kb-raw-v1 | 用户原文 |
| 解析文本 | source_text / kb-text-v1 | 当前文本输入的原文副本，来源指向原件 |
| 整理结果 | knowledge_import_manifest / writing-kb-document-v1 | 片段、摘要、检索词、精确引用、模型回执 |
| Wiki 页 | wiki_page / wiki-page-v1 | 摘要、主张、支持组和 UTF-8 证据定位；可由现有 WikiReader 阅读 |
| 操作记录 | retrieval_trace / kb-run-v1 | 输入摘要、操作状态 |
| 问答记录 | retrieval_trace / kb-answer-trace-v1 | 排名、实际输入包、模型响应、引用、配置与用量 |
| 历史回测记录 | retrieval_trace / kb-evaluation-v1 | 旧实现产物保留，不再新增；当前报告写独立文件目录 |
| 历史回测配置 | retrieval_index_manifest / kb-profile-v1 | 保留历史，不再读取用于运行策略；evaluate/profile 请求已移除 |

知识产物使用 `knowledge` owner；所有 head 以 `knowledge.kb.` 开头。资料分别维护 latest 和 active，最新候选不会覆盖旧的已确认版本。只有 active 或显式请求且仍确认的精确版本参与查询。撤销同时作用于该版本的整理结果、原件、解析文本和 Wiki，保留历史内容。

片段定位登记在已有 `knowledge_spans`，包含来源版本、解析器版本、UTF-8 字节范围与哈希。检索时重新验证内容、定位和决定。模型摘要仅供检索增强，交给回答模型的证据始终是原文。评测、答案、运行回执不进入知识语料。

## RAG 策略

- literal：原文规范化后完整子串匹配，作为简单基线。
- lexical：中文二元字串与其他文字词项，使用 BM25 风格评分（k1=1.2、b=0.75）。
- enriched：相同评分，检索表示增加作者审阅过的标题、摘要与关键词；返回原文证据。

运行策略固定为 enriched + JSON；回测建议不会修改运行配置。没有接入向量模型或使用现有 `retrieval_vectors` 表，不称为向量/混合检索。这里的 RAG 是有版本、范围和证据定位的词法增强检索。策略只在已授权的本项目语料内排序；显式来源跨项目或失效直接失败，不自动回退到其他资料。

## 生命周期与限制

Remote 仅接受宿主 owner；所有请求经过中间件。查询适配层只获得 `KnowledgeReader`，不持有管理或数据库权限。模型调用在数据库短事务之外进行。

入库/回答派发前持久化操作 ID 和输入哈希，相同 ID/不同输入拒绝。已完成操作重放回执；已开始但没有完成回执的操作不自动重新调用模型。超时/取消不会撤销已提交数据。进程中断后的未知调用需由操作者核对，不自动假定未计费。

模型调用上限 120 秒；入库每批最多 8 片，整个任务按批数分配截止时间，模型配置变化即失败；同一核心最多两项入库/问答任务并发。独立回测只输出模型输入包并回放观测文件，不使用本核心的持久化问答入口。输出最大 160000 字符且必须正常结束。没有后台任务调度或自动恢复派发。用量未获提供方返回时存 null，不伪造 Token 或费用。

单资料最多 60000 UTF-16 单元，按 600 Unicode 码点/80 码点重叠切分，最多 100 片，超过时明确要求拆分。查询最多 100 文档、5000 片段、topK 1–20、证据包 1000–40000 Unicode 字符（包括引用元信息）。这不是模型 token 预算，不保证适合所有小上下文模型。尚未进行大库并发压测。

已经实现结构、引用和作用域验证；引用通过不意味着断言被证据语义支持。候选审阅和后续语义评审仍必要。未宣称零提示词注入或零幻觉，也未实现人物章前知情投影、跨来源规则依赖闭包、PDF/OCR/URL 导入和自动正文发布。
