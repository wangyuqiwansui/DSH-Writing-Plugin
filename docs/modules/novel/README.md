# 小说模块：内存版手动创作工作区

日期：2026-10-24（Asia/Shanghai）。实现工程为 `DSH-Writing-Plugin`，当前实现手动创作与版本交接，完整自动创作链尚未实现。

## 使用入口

在写作工作台点击“小说”，或在首页点击“创建小说 / 继续创作”。本地组件预览：运行 `npm run preview`，打开 `http://127.0.0.1:4173/?page=novel`；也可设置 `PORT`。

1. 从[作者人格](../author-persona/README.md)或世界观页面加入已发布的精确版本，或在资产配置中手动登记已有内容及参考资料，明确选中双资产后创建小说。小说仅保存本次会话的内容投影和来源版本，不复制维护全局人格资料库；新版本不会静默重绑。
2. 创建后进入小说设定。所有模块始终可访问，角色可先于总纲独立建档。不完整内容可保存为草稿；满足字段、来源、范围和状态交接后，由作者确认精确版本。
3. 总纲维护全书方向和各卷剧情；单元引用卷事件；章节独占逐章剧情及事件分配。每层保留稳定 ID、父级、顺序和版本。正文从章节直接进入，不再生成章纲或章卡。
4. 正文可手动编辑、保存多个版本、查看来源和比较历史。不会标为正式正文，也不会写入角色事实。
5. 数据仅在当前客户端会话内存中保留。工作台页面切换保留编辑缓冲；刷新、关闭或卸载后清空。先保存，再“导出已保存版本”获得 `.novel.json`。导出不包含尚未保存的编辑缓冲。
6. 导入会创建新身份的小说，映射父级和角色引用，取各对象最新内容作为候选。原文件保存的历史、确认与 hash 仅作为备份资料；导入不会继承其权威资格。按资产、设定、角色、总纲、卷、单元、章节逐项复核并另存来源，再确认。原小说不被覆盖。

2026-10-26 补充：小说编辑页的“世界观材料”可查询已确认绑定的世界观精确版本。支持名称/别名、显式消歧、规则依赖和字符预算；仅提供作者规划材料，不自动判断角色知情、时期适用，也不调用模型或保存上下文。世界观换版后仍查询旧绑定；手工登记的纯文本资产需先补正式结构化来源。详见[世界观查询合同](../worldbuilding/README.md#材料查询合同)。

## 已实现范围

| 模块 | 可操作内容 | 确认及失败边界 |
| --- | --- | --- |
| 资产配置 | 手动登记、预览、明确双绑定、可选参考、绑定修订及影响清单 | 资产类型、可用性和 ID 校验；同一业务幂等键只创建一次；缺双绑定不创建 |
| 小说设定 | 定位、前提、叙事、篇幅与收束、边界和未决项 | 确认必填；正整数字数区间；连载可不填总章数；未决项未处理不可确认 |
| 总纲 | 全书梗概、主线、承诺与结局、分卷剧情、原因、事件和人工检查记录 | 空卷壳不可确认；局部确认；相邻卷交接检查 |
| 单元 | 完整可读剧情、因果事件、父卷事件引用、入口和出口 | 悬空事件、未确认或过期卷、交接不一致阻塞；显示父卷事件缺口 |
| 章节 | 逐章剧情、主单元、事件片段职责、角色、场景及表达要求 | 精确来源、角色范围与确认检查；部分分配不冒充完整；章节字数可继承设定 |
| 正文 | 章节目录、人工编辑、字数统计、来源阅读、历史差异 | 草稿或导入候选；正式入库接口明确拒绝；后续章节提示前序正式事实未接入 |
| 角色库 | 独立创建人物身份、别名、档案、初始状态和初始关系说明 | 按小说隔离；同名保留独立 ID；不消费作者人格为事实；不提供写后事实接口 |

共用能力包括 SHA-256 内容摘要、精确版本来源、版本绑定确认记录、预期版本并发检查、拒绝/撤销、递归来源新鲜度、下游影响、候选导入和失败时保留输入。业务状态与来源新鲜度独立呈现。上游草稿不替代旧权威；新版本确认或旧版撤销才影响引用它的下游。下游不会静默重绑。更换作者人格只影响表达消费者，更换世界观影响事实消费者及其下游。

事件格式为每行 `事件 ID | 内容`；下游引用用逗号或换行分隔。程序只验证身份、类型、版本、事件归属和确定性结构。状态交接当前使用去除首尾空白后的精确文本相等检查，不能推断两段不同措辞是否语义等价。因果、动机、世界冲突和文学质量由作者填写人工检查记录并核验，不宣称已完成 AI 语义评审。单元对卷事件的重复引用会使完整性保持未完成；多章可分段承担同一单元事件，作者须核对片段职责。

## 架构与数据所有权

- `contracts/index.ts`：模块/对象类型、版本、来源、确认、命令、工作区快照。
- `domain/fields.ts`：各模块字段、确认必填和类型/数值检查；不含 I/O。
- `application/service.ts`：唯一会话数据所有者。创建、保存、确认、拒绝/撤销、影响分析、导入导出通过显式命令。提交前校验当前版本，异步 hash 后重新检查；导入先在独立工作区整体校验再提交。快照深冻结，不允许页面修改内部状态。
- `client/controller.ts`：编辑缓冲、页面定位、忙碌状态、错误反馈及订阅清理。不直接写其他模块的数据。
- `client/world-context.ts`：会话内材料查询、绑定核验、取消/超时和断连恢复；通过 `WorldBackend` 公开只读合同交接，不持有可写世界文档。`application/service.ts::worldSource` 只解析当前有效的已确认绑定。
- `client/NovelPage.tsx`：七入口及编辑、参考、历史界面；`client/index.ts` 通过既有 `WorkbenchController.register` 注册 `novel`。
- 工作台拥有控制器生命周期；卸载释放订阅、缓冲、幂等表及会话记录，晚到的异步保存不能提交。

小说写入没有数据库表、迁移、独立 Host remote、模型请求或文件系统自动保存；只读材料查询复用世界观 Host 的公开接口。没有导入现有 `story.ts` 的有限 schema 后再塞入未知字段；本次使用独立明确的 `writing-novel-memory-v1` 合同。未来接入数据库时复用统一 `writingStorage` 和根 `databasePath`，迁移走 `npm run db:init`。

## 当前能力边界

小说目前仅在会话内存中保存，未接入数据库持久化、AI 候选生成、自动评审、正式正文入库、写后事实维护或工作流扩展运行器。人物关系仅保存初始档案和文本说明；复杂拆并重排、宿主深链接、模型工具循环尚未接入。导出保留历史，导入只采纳最新内容为新候选，不恢复原确认状态。

## 验证

根目录 `tests/` 仅留本地，不随 Git 分发。以下业务回归需要具备本地测试文件；公开 `npm test` 仅构建并运行独立回测自检。

文档基线和已安装开发 SDK 均为 DSH `0.2.1-rc.2`、Cordis `4.0.5`；不是针对相邻旧工程 alpha.4 的兼容声明。

```powershell
npm run test:local
# UI 检查需先运行本地预览，并提供本机 Playwright/Chromium 路径
$env:PREVIEW_URL='http://127.0.0.1:4188'
node scripts/check-novel-ui.mjs
```

组件交互和真正 DSH Host + Web 验证分别记录。隔离宿主测试不操作用户日常 profile，不调用付费模型；原生 Electron 窗口及用户真实组合未在本轮操控。
