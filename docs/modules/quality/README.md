# 质量检测实施说明

2026-10-24 更新。质量检测已在 `DSH-Writing-Plugin` 实现为可独立启停的 Cordis 模块，入口 `dsh-writing-workbench/quality`，服务 `writingQuality`，页面名称“质量检测”。只保留 **正文质量检测、L0 全局规则、L1 项目规则**，不包含工作流编排、自动重写、发布或后台巡检。

布局采用检测类型说明、规则层级卡片和编号规则列表。沿用本工程黑白灰样式；移除“历史报告”“污染观察”入口，不提供拆章/大纲检测或 L2。

## 已实现功能

| 功能 | 当前行为 |
| --- | --- |
| 规则管理 | L0/L1 层级卡片、编号规则列表；新增草稿、修改产生新版本、显式启用、停用。可编辑名称、说明、来源和检查方式，正文范围固定。修改草稿时，旧生效版本继续有效。 |
| 内容选择 | 读取当前库的项目与章节正文最新版本；检测请求固定完整 VersionRef，结果保存当时原文。 |
| 机器检测 | 空内容、异常控制/替换字符、正文外围代码围栏、显式过程标签；自定义精确包含/禁止文本及命中后待复核的文本提示。不会清洗后再检测。 |
| 语义审阅 | 可选使用顶部统一模型选择，单次 prepared call，逐规则覆盖检查、精确证据校验，保留模型原始返回。不自动修复 JSON 或重试调用。 |
| 本次结果 | 检测页面内展示执行状态、内容结论和逐项依据；目标或生效规则变化后标记“版本已变化”。停止等待后可“核对本次结果”，只读查询已提交操作，不重新派发。 |
| 原文定位 | Unicode 码点坐标，零起点半开区间；展示报告中保存的完整原文并高亮精确引文。规则来源说明与版本一同冻结。 |
| 搜索 | 当前层级的规则名称、内容、来源与状态筛选；章节正文名称搜索。参数化字面量查询，`%`、`_` 不作为通配符。默认 30 条，API 最大 100 条。 |

## 使用

1. 构建后在 DSH 工作台选择“质量检测”，使用“数据库”页面选择已升级的数据库。
2. 默认打开“规则管理”的 L0 卡片；L0 无需项目，L1 需选择当前项目。创建草稿后点击“启用”。没有启用的规则不会参与检测；空规则集只执行基础检查。
3. 点击“检测正文”，选择项目及检查范围，在章节列表中“预览检测”，核对正文版本与生效规则后再“开始检测”。
4. 在本页查看本次结果及原文高亮。机器检测没有完成的语义规则显示“待复核”，不显示整体通过。停止等待或请求失败后，使用“核对本次结果”；详情读取失败可重新读取同一结果。

规则来源目前是用户填写的说明文字，存入不可变规则版本。此模块没有加载外部规则文件、自动导入源系统默认集或将项目偏好转换为规则。通用来源资料浏览仍由 Wiki 提供；本轮不把来源文字伪装成已验证的文件引用。

目标仅为 `chapter_body`，列表使用已有产物键作为标题。支持 text/JSON 原始版本，单版本上限 800 KB；JSON 按保存时原始文本检查，不猜测正文提取字段。正文以 JSON 保存时提示人工核对格式约定。公开接口在访问存储前拒绝大纲目标与新的纯大纲规则。

收敛页面不删除旧数据，也不修改 schema v5。旧报告读取契约保留兼容性；页面仅在核对本次操作时使用精确操作标识读取报告，不浏览历史或污染日志。纯大纲规则在 SQL 分页前排除；旧规则若仍有生效正文版本，则保留可见性，编辑保存后产生正文范围的新草稿。

## 数据库升级

新增 [005_quality.sql](../../../storage/migrations/005_quality.sql)，该迁移定义质量模块的 v5 增量；全库当前目标为 **schema v6**。只新增 `quality_rules / quality_rule_versions / quality_reports / quality_commands`，001–004 保持原文件；没有改写已有正文、Wiki、项目或原表数据。

质量模块与 Wiki 共用根工作台数据库，不单独配置或初始化。L1 规则和正文检测需要使用者自己的项目及章节版本。

加载插件或打开页面仍不会自动迁移。对需要升级的本地数据库，使用数据库页面给出的命令，或按实际路径运行以下示例：

```powershell
npm run db:init -- --db "<本机数据库绝对路径>"
```

现有管理器在升级前生成一致性备份，并校验旧内容摘要、实例、外键与结构。迁移中断整笔回滚。升级后在数据库页面刷新并检查。数据库服务采用全库 schema 校验，因此连接 v4 时其他存储页面也会提示需要迁移；不兼容降级不自动执行。

质量检测没有独立初始化步骤；其迁移与 Wiki、公共存储通过同一命令完成，登记见 [统一初始化清单](../database/initialization.md)。

## 装配与独立启停

主插件默认装配质量模块，支持配置 `quality: false` 或 `quality: { timeoutMs: 120000 }`。超时范围为 1000–300000 毫秒。普通配置变更触发 Cordis 重挂载。

需要仅启停质量模块时，将主插件 `quality` 设为 `false`，使用独立稳定配置行装配，二者不可重复启用：

```yaml
- id: writing-workbench
  name: dsh-writing-workbench
  config:
    databasePath: 'C:/path/to/novel.sqlite3'
    quality: false
- id: writing-quality
  name: dsh-writing-workbench/quality
  config:
    timeoutMs: 120000
```

这是独立装配的 profile 配置行示意。更新行的 config 时应保留同一行其他字段（如 `defaultModel`），因为宿主会整体替换 config。

`writing-quality` 必需依赖 `writingStorage`；缺失时 PENDING，provider 移除/恢复时自动卸载/重新装配。语义能力在使用点查询 `writingModels`，不阻塞机器检测、规则和结果读取。RPC 为 `writingQualityRemote.invoke`，要求宿主所有者身份并严格验证请求。

按实际 rc.2 Registry 约束，同一 npm 包的 Remote contribution 只能注册一次。**根工作台拥有聚合 RPC 描述符与导航入口，质量子插件拥有实际服务和 Remote 实例。** 独立停用后根入口保留，刷新或调用会显示服务不可用；不会重复注册整个包。客户端工作台卸载时撤销页面、订阅和请求。独立服务也可由宿主消费者调用 `ctx.writingQuality.engine.invoke()`，浏览器集成使用根工作台。

卸载先封闭新请求、撤销本模块 AbortSignal，等待被中断的本地任务结束；每个异步边界同时等待取消信号，即使 provider 忽略信号也不无限等待。旧 generation 的回调不能修改新实例。共享存储不会被质量模块关闭，数据不会因停用删除。这里验证的是 Cordis 启停与重挂载；没有声明源文件监听 HMR。

## 数据与执行契约

- L0 使用实例范围及 `projectId: null`，L1 必须引用现有项目；不创建虚构系统项目。
- 所有修改通过共享存储的 `qualityCommand`，操作标识在范围内持久幂等，同标识不同输入拒绝。查询使用可撤销的 `openQualitySnapshot`；不公开 SQL 或连接。
- 规则修改使用 `expectedRevision`；预览与执行之间校验原文完整引用、最新状态、生效规则和检测器配置摘要。精确包含/禁止同一文本的硬规则冲突会在派发前拒绝。
- 报告 schema 为 `writing-quality-v1`，检测器为 `quality-detectors-v1`。报告保存目标原文、完整版本引用、生效规则快照、检查结果、原始模型文本、模型选择和 generation。规则版本与终态报告不可变。
- 模型调用在 SQLite 事务之外。通过现有 `writingModels.prepare()` 捕获统一选择和实际 adapter 配置，再持久保存模型选择并调用，不创建独立 API Key 配置。输出上限请求 8000 tokens，原始结果文本上限 200000 UTF-16 单元，最多 100 条生效规则。
- `succeeded` 仅表示检查执行结束，内容结论可为 `passed / issues_found / needs_review`。`failed / cancelled / unknown` 不产生通过结论。语义 issue 须提供能逐字验证的原文；缺项、重复项、未知规则、不匹配 quote/offset 均失败并保留原返回。
- 已发起模型调用后取消、超时或连接中断，不能证实远端是否结束时记录 `unknown`；界面停止等待不等于确认供应商取消。卸载中的报告仍保留原运行记录，新实例将旧 generation 的未终结记录投影为 unknown，不自动重新派发。
- 分页使用范围与过滤条件明确的 `offset/limit`，无可跨项目复用的隐式 cursor。UI 切换项目/条件后取消旧查询并丢弃晚到结果；查询异常不伪装成零记录。
- 文本是数据：不执行规则脚本、源文件指令、模型工具调用或原文修复。不会给出未经校准的“AI 生成概率”或质量总分。

## 版本与验证

根目录 `tests/` 仅留本地，不随 Git 分发。以下业务回归需要具备本地测试文件；公开 `npm test` 仅构建并运行独立回测自检。

目标 DSH 为 `0.2.1-rc.2`。执行 `npm run test:local` 验证规则状态、精确版本、权限、失败与恢复路径；组件演示可另用 `scripts/check-quality-ui.mjs` 配合 Playwright 检查。日志、截图与运行数据库仅保存在本地；组件预览不替代原生宿主验收。

## 本地预览

```powershell
npm run build
$env:PORT='4187'
npm run preview
```

打开 `http://127.0.0.1:4187/?demo=quality`。预览 API 仅监听回环地址并校验同源 JSON 请求，使用临时 SQLite 与合成小说；写操作仅影响该临时库，不修改 DSH 配置、用户数据库或调用模型。默认生产插件不启动此服务器。

浏览器验收可设置 `PLAYWRIGHT_MODULE`、`CHROMIUM_PATH` 和 `PREVIEW_URL` 后运行 `node scripts/check-quality-ui.mjs`。
