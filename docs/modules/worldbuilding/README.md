# 世界观：树状设定、版本发布与小说材料查询

当前支持树状设定编辑、共享数据库存储、正式版本发布及小说绑定版本的只读材料查询。规范格式为 v3；v1/v2 导入时清理旧目录字段。可选模板已移除，AI 提取、自动生成和语义检索尚未实现。

## 使用

1. 在工作台“数据库”页连接已经初始化的共享数据库。当前工程迁移目标为 v6；未初始化或旧版本时页面显示原因，运行统一命令 `npm run db:init -- --db "<本机绝对路径>"` 后刷新。世界观启动不建库、不迁移、不写入默认内容。
2. 打开“世界观”，新建世界，填写名称、简介；时代、空间按需填写。已移除可选模板。普通背景只需名称与描述。
3. 在设定目录添加根设定、子设定，通过“上级设定”调整层级，搜索保留祖先目录。关键设定填写运行规则、条件、代价和适用边界；“无代价”“无例外”等需要明确写出。共享规则仍可在节点内使用引用。
4. 页面仅提供世界范围、设定目录两个区域；硬规则、关联关系、术语别名模块已移除，历史数据与原查询兼容语义保留。作者确认、客观事实/传闻、有效/失效独立表达；已确认传闻只确认说法存在。失效设定保留原适用时期与失效原因，现实参考记录出处、定位及适用时期。
5. 保存草稿，运行校验，勾选作者审阅后发布精确版本。草稿允许业务未完成；正式发布拒绝阻断问题。每次改动需要重新保存并确认，旧校验意见不能放行新内容。
6. 当前正式版本可“加入小说资产”，随后在小说的资产配置显式选择、确认。发布新世界版本不会修改现有小说绑定。页面不再提供总览与摘要、历史版本、待确认事项或“旧目录信息”区域；历史正文与版本身份保留，旧目录字段可通过下述显式维护清除。
7. 小说编辑页的“世界观材料”输入名称、别名或用空格分开的关键词，选择字符预算后查询；留空只取核心与硬规则。结果展示精确来源、入选依据、歧义和缺口。手动登记的纯文本世界资产没有结构化来源，需先从世界观页加入正式版本。

小说仍采用既有会话内存模式；导出的小说文件保留世界观精确 `VersionRef` 与当时的摘要，刷新前仍须导出小说。世界观本身保存于共享数据库，刷新或插件重挂载后可恢复。

## 数据与职责

| 所有者 | 职责与契约 |
| --- | --- |
| 世界观 domain | `writing-world-v3` 邻接表记录，新增可选 `parentId`，历史 `entryType` 仅兼容保留；v1/v2 输入验证后删除 `categories` / `category`；严格字段/规模检查、有效业务引用校验、规则边界与术语消歧；旧 `questions` 仅归档，不参与业务校验；不调用模型或 SQL |
| 世界观 application | 精确来源查询、保存与发布入口；校验精确候选、版本比较、作者确认；维护不可变版本、改名旧称、正式版本指针及回执 |
| 中间件数据端口 | 世界观请求经过 `writingMiddleware`，通过限定 `story` / `writing-world-library` 的端口使用内部存储；复用 001/002 的 `resource`、不可变版本、head、命令回执、决策与 outbox，沿用完整 v6 校验；无新增表或迁移 |
| Host / Gateway | `writingWorld.invoke`；依赖已声明的 `typert` 与 `writingMiddleware`；仅宿主 owner 可读写，不修改 profile 或外部资源 |
| Client | 范围、树状目录、功能测试集生成与导出；控制器保留切页草稿、取消/超时恢复；卸载清理请求和监听 |
| 小说 | 显式导入正式版本，解析当前已确认绑定；独立查询控制器仅持有临时材料，通过公开接口读取原版本，不写世界观存储、不自动跟随 active head |

共享库中的资料库项目固定为 `writing-world-library`，存储 owner 为现有 `story`，产物 key 为 `world-<worldId>`。新增、导入、保存、导出统一使用 `writing-world-v3`。v1/v2 的读取投影会清理旧目录，读取本身不修改数据库；未做历史清理的旧版保存会形成 v3 候选。`story.world.<worldId>.latest`、`.active`、`.version.<n>` 分别指向最新保存、最近正式和精确历史版本；常规业务写入仅经世界观领域服务，不改写历史。

世界版本、记录 ID、时间、作者、内容摘要与确认记录由系统维护。关系、规则、术语使用稳定 ID 引用；改名自动追加旧称。删除仍被引用的记录时报告受影响对象，拒绝删除；隐藏分类与删除记录分开。

## 材料查询合同

`writingWorld.invoke({ action: 'query', sourceVersion, query })` 仍经过 owner Gateway 与 `writingMiddleware`。`sourceVersion` 必须完整匹配同实例、世界观资料库、内容哈希及已发布且仍确认的版本；不存在、已撤销、草稿或伪造引用返回明确失败，不改用最新版本或旧摘要。仅当精确旧引用匹配目录清理回执时，返回同一版本的新哈希及 `sourceRepair`；小说据此同步该资产和历史来源引用，保留正文、版本状态及确认记录。跨版本或未匹配的旧哈希不能修复。

`query` 包含 `text`（最多 600 个 UTF-16 单元）、`recordIds`（显式选择的稳定 ID）、`maxCharacters`（200–100000 个 Unicode 码点）及 `maxRecords`（1–100）。当前不调用模型或外部检索服务。

查询顺序为核心与全部硬规则 → 显式条目 → 名称/别名/正文匹配 → 一层直接关联。每个入选条目补齐完整 `ruleRefs` 和硬规则优先关系；条件、代价、例外、原适用范围及传闻/失效标签一并保留。相同名称或别名返回候选供选择，候选内容不冒充已确认事实。完整目录路径参与匹配，精确路径可消解不同父节点下的同名设定。

核心、显式条目及必要规则超过预算时返回空材料和 `REQUIRED_BUDGET`；其他匹配无法完整加入时返回 `complete: false` 与缺口，不截断规则。预算统计的是字符，不能直接当作模型 token。查询结果为 `writing-world-context-v1`，`purpose: author_planning`、`scopeReviewRequired: true`；`complete` 仅表示本次确定性选择没有检测到缺口，不表示语义召回完整、时点正确或角色已经知情。

浏览器断连、数据库变化、小说/模块切换、保存或确认绑定、超时、取消与卸载会取消或使旧结果失效；晚到结果须重新核对绑定，不能进入新范围。读取失败保留输入供重试。材料不自动存入小说正文或上下文库。

## 失败与恢复

- 并发保存要求最新版本号一致；冲突保留本地输入，可导出后载入最新版本合并。没有静默的最后写入覆盖。
- 相同内容保存返回现有版本；同一操作 ID 重试回放原回执，换内容复用 ID 被拒绝。
- 提交响应丢失时暂停新的写入，使用“核对提交结果”查询原命令回执；查无回执才以原 ID/原内容重试。取消不撤销此前已保存版本。
- 断连或数据库切换保留输入；原库草稿不能提交到另一实例。未保存新世界也保留在本次会话选择列表。浏览器刷新、关闭或插件卸载会丢失未保存输入，需先保存或导出。
- 旧 `questions` 的问题、状态和依据正文保留；依据中序列化的旧记录或世界文档也删除目录元数据。不再自动重开、不阻断发布或删除设定，也不进入小说摘要的校验提示。新的发布确认使用 `world-validation-v2`；目录清理保留原确认策略与作者记录。结构格式与规模检查仍用于拒绝损坏文件。
- 数据库/依赖不可用明确展示状态；不伪造空库保存成功。未知旧格式拒绝导入，保留原文件；页面读取和插件启动不重写历史库。

## 显式清理历史目录

该维护命令只在明确要求清除历史目录数据时使用。先导出会话小说、停止旧 Host，构建新版后预检，再显式执行：

```powershell
npm run build
node scripts/cleanup-world-directories.mjs --db '<现有数据库的本机绝对路径>' --report '<预检报告.json>'
node scripts/cleanup-world-directories.mjs --db '<相同路径>' --apply --report '<清理报告.json>'
```

基础设施维护器持有写锁后生成一致性备份，在单个事务内清理全部世界版本、保存回执、事件及嵌入的旧目录元数据，重算内容/语义哈希并修复精确引用。世界 ID、版本 ID、revision、正文及作者确认不变。事务内临时解除的不可变 UPDATE 约束按原 SQL 恢复，并校验完整 schema、外键和完整性；任何失败回滚。正常业务接口仍保持不可变历史，数据库 schema 仍为 v6。

重复执行没有变更；路径/内容损坏、未知派生产物或未适配引用会拒绝提交。备份用于运维回滚，不参与产品读取。清理回执只保留同一版本的前后引用及新摘要，不保留旧目录内容。外部小说文件应按回执更新或导入新版后查询以同步来源，再导出保存；命令不会扫描任意用户目录。完成后启动新版 Host 与 Client。

## 本阶段边界

- 支持 `writing-world-v1` / v2 / v3 JSON 导入，统一导出 v3，不再输出旧目录字段。导入产生新世界候选，保留原稳定记录 ID 和 `extensions`，不继承发布确认。尚未实现旧 `writing-plugin` 世界观格式的映射、去重和事实移交。
- 关键规则的条件、代价、范围、引用、优先关系循环与完全重复可确定性检查；复杂文学自洽、现实资料真实性及隐性规则矛盾仍需作者审阅，不宣称自动语义证明。
- 时期目前是作者文本，历史版本可精确回看；尚无跨历法时间计算、按章节时期自动过滤或角色/剧情事实写后回传。
- 关系等旧模块已退出界面，保留历史内容兼容。AI 提取/生成、自动资料抓取和剧情编排未接入。
- 单世界内容上限 200 万字符、各列表 500 项、历史 500 版本；小说资产仍遵循既有 50 万字符限制。未来超限可在不改写历史的前提下扩展分页策略。

## 验证入口

根目录 `tests/` 仅留本地，不随 Git 分发。以下业务回归需要具备本地测试文件；公开 `npm test` 仅构建并运行独立回测自检。

文档基线与开发 SDK：DSH `0.2.1-rc.2`、Cordis `4.0.5`。

```powershell
npm run build
node --test tests/worldbuilding.test.mjs tests/world-query.test.mjs
# 全量既有回归
npm run test:local
# 隔离的安装版 Host + Web；需可用的 Playwright 与 Chromium
$env:PLAYWRIGHT_MODULE='<本机 Playwright index.mjs>'
$env:CHROMIUM_PATH='<本机 Chromium 可执行文件>'
node scripts/check-world-host.mjs
```

Host 脚本只创建独立 home/profile/数据库，使用回环端口并清理本次进程；不会升级用户日常数据库。原生 Desktop 窗口和用户日常 profile 不在其验收声明内。

## 树状存储与 LLM 召回方案（2026-10-27）

已实现：以 `records[]` 邻接表保存树，每条记录使用稳定 `id` 和可选 `parentId`；缺省父 ID 表示根节点。数组顺序决定同级顺序。接口通过 `settingTree` 投影为 `{ record, children }[]`，编辑、导入、保存和重新读取共用同一结构。旧记录自然成为根节点；拒绝缺失父节点、自引用和循环，父节点有子节点时禁止删除，需先移动或删除子节点。完整版本仍保存在共享 resource JSON，不新建表、不修改历史版本，也不触发初始化。

选择邻接表而不是重复嵌套正文：稳定 ID 不随移动或改名变化，一条正文只存一次，现有规则引用继续有效；父路径按版本实时派生，不保存容易过期的路径副本。现有上限 500 条，内存检索足够支持当前规模。材料包含命中节点的完整路径、稳定 ID、版本来源及原有规则边界；路径仅用于定位，不把父节点所有正文或兄弟节点自动视为命中事实。

测试入口：在「世界观功能测试集」生成名称基准模板，编辑自然语言问题、预期条目 ID 和 dev/test 分组后导出文件。页面不运行 Remote 查询、不计算成绩、不修改数据库或配置。独立回测通过 `backtesting/` 读取世界观文件快照，调用同一生产查询纯函数，输出逐数据集召回、精确率、完整证据覆盖率和 MRR，见[独立回测](../../../backtesting/README.md)。

独立回测已支持人工标注问题集与对应检索指标。后续建议（尚未实现）：确认词法漏召回后，再增加按版本/节点分块的 FTS 与向量混合召回、重排。索引记录至少包含世界/版本/节点 ID、内容哈希、祖先路径、正文及确认/有效性状态，先隔离版本与权限，再检索，最后补齐规则依赖。派生索引必须可重建；新增索引表时通过连续编号迁移和统一初始化器接入，不能在页面打开时建表。当前未接入向量索引或模型生成评测。
