# 雾港校时员：可选合成示例

本目录只保留 `data.mjs` 合成定义、`create.mjs` 生成脚本和 `verify-export.mjs` 验证脚本。样例包含作者人格、世界观、6 名角色、2 卷、4 个单元、8 章计划和完整测试稿；不作为首次启动的默认业务数据。

## 生成文件

```powershell
npm run example:generate
```

命令构建项目，在内存中通过真实领域服务检查字段、规划交接及导入契约，并把结果写入 `local-output/examples/fog-harbor/run-<随机后缀>/`。输出目录随命令打印。生成过程不连接数据库、不写 DSH profile、不调用模型，也不覆盖上次输出。

该本地目录包含 `fog-harbor.novel.json`、`author-persona.json`、`world.json`、`manuscript.md`、`manifest.json` 和预检结果。全部由 Git 忽略。默认导出的人格/世界资料是手动资产，不绑定任何机器的已发布版本；需要体验时主动在对应页面导入，导入内容为候选，仍需作者确认。

## 可选安装到专用测试 profile

只有主动使用以下命令才会向指定 profile 已配置且已初始化的数据库保存/发布样例。不要在日常数据库上进行自动验收：

```powershell
node examples/fog-harbor/create.mjs --install --profile '<专用测试 profile 的绝对目录>'
```

脚本不会初始化或迁移数据库。它通过中间件任务和受限模块端口保存，遇到被修改的同 ID 样例会拒绝覆盖。输出仍位于独立本地目录，此模式的清单才包含该测试实例的正式版本引用。

## 可选原生导出核验

安装样例后，将对应小说包导入专用测试会话；在资产配置中刷新来源并另存版本、确认资产配置，保持其余对象为候选。将界面导出保存为同一运行目录中的 `current-session.novel.json`，再执行：

```powershell
node examples/fog-harbor/verify-export.mjs --input '<上述本地运行目录>'
```

此验证只读取文件和内存服务，报告默认写入同一本地目录。它需要使用者本次取得的原生导出，不随仓库提供历史会话备份，也不是默认生成命令的依赖。

小说目前仍为会话内存数据；导入不会恢复历史确认状态。当前导出器收集资产依赖来源引用，导入后直接再次导出可能遗漏资产，需先刷新资产来源。正文第 2–8 章保留“前序正式事实尚不可用”的限制；样例通过不代表文学评审、正式正文入库或写后事实维护已实现。
